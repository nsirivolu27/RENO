GOAL

Make Reno’s real photorealistic before-and-after renovation workflow demonstrably work end to end in the running Replit preview.

A user must be able to:

1. Upload a real photograph of a room.
2. Choose the room type and design style.
3. Select Restyle or Renovate.
4. Describe furniture, lighting, wall paint, flooring, fixtures, budget, and items that must remain.
5. Send the original room photo and design instructions to a real image-editing provider.
6. Receive a photorealistic redesigned version of that same room.
7. Compare the exact original and generated result with the draggable before/after slider.
8. Save the real result to Projects and open it in the client presentation view.

The app must clearly distinguish a real AI result from a demo fallback. Never present a CSS illustration, stock photo, or unrelated image as an AI renovation.

REAL IMAGE REQUIREMENTS

The provider must perform image-to-image editing using the uploaded photograph as the visual input. It must not generate a random room from text alone.

The renovation prompt must instruct the model to:

- Preserve the exact camera position, lens perspective, crop, room dimensions, ceiling height, structural layout, doors, windows, openings, and permanent architecture.
- Keep requested must-retain elements unchanged.
- Redesign furniture placement, lighting, wall paint and finishes, flooring and rugs, cabinetry, fixtures, window treatments, and decor according to the brief.
- Maintain physically believable scale, perspective, material texture, reflections, daylight, artificial lighting, contact shadows, and object placement.
- Produce one finished photorealistic interior photograph.
- Avoid illustrations, sketches, mood boards, split screens, collages, CGI appearance, text, labels, logos, watermarks, people, and impossible architecture.

Restyle mode may replace furniture, lighting, textiles, and decor but should preserve built surfaces.

Renovate mode may additionally change paint, wall finishes, flooring, cabinetry, built-ins, countertops, plumbing fixtures, and architectural finishes while preserving the room’s structural geometry.

HONEST RESULT STATES

Implement clear result metadata returned by the API:

- success: boolean
- resultImageUrl: string only when a real image exists
- provider: gemini or openai
- model: actual model used
- isDemo: boolean
- requestId or renderId
- errorCode when unsuccessful
- safe user-facing error message

The Studio result must display one of these states:

1. “Photoreal AI render” with provider/model metadata when a real provider succeeds.
2. “Demo preview only” when showing the abstract local concept.
3. A visible actionable error when the provider fails.

Never silently replace a failed real render with the demo visual while claiming generation succeeded.

When the real provider fails, preserve the uploaded image and completed brief so the user can retry. Translate common failures into useful messages:

- 401/403: API key invalid or model unavailable
- 429: provider quota or rate limit reached
- 413: image is too large
- timeout: render took too long
- unsupported image: request a JPEG, PNG, or WebP
- provider returned no image: explain that no result was produced

IMAGE HANDLING

Before upload:

- Accept JPEG, PNG, and WebP.
- Correct mobile image orientation if needed.
- Resize very large images while retaining good presentation quality.
- Preserve the original aspect ratio.
- Target approximately 1600–2048 pixels on the longest edge.
- Avoid excessive base64 payloads.
- Show the selected original photograph before generation.
- Do not overwrite or mutate the original image.

The generated result must use the same aspect ratio and comparison viewport as the original.
